# 쮸글(JJUGLE) Chaos v4.9.8 — Conversion Lock

실전 PGN에서 반복적으로 관찰된 **승세를 공격 스타일 선택으로 날리는 현상**을 완화하는 후보 버전입니다. 정확한 v4.9.7 운영 소스로부터 개발했습니다. **이 ZIP을 내려받는 것만으로 운영 서버나 GitHub가 바뀌지 않습니다.**

## 변경 사항

1. **승세 보존:** 객관 탐색 점수가 +40cp 이상이면 스타일을 위해 허용하는 평가 손실을 단계적으로 줄입니다. +100cp~+199cp는 최대 12cp, +350cp~+699cp는 최대 5cp, +700cp 이상은 0cp입니다. 평가 점수 자체/TT는 변경하지 않습니다.
2. **룩 엔드게임 청산 방지:** 퀸 없는 우세한 엔드게임에서 스타일 때문에 룩을 내주고 상대 룩으로 교환하게 만드는 수가 선택되면, 이미 완료된 객관 탐색의 더 좋은 수를 유지합니다. 객관 탐색이 교환 자체를 최선으로 판단한 경우에는 막지 않습니다.
3. **명백히 무보상인 마이너 희생 방어:** 비숍·나이트가 폰 하나를 잡고 상대 킹에게 즉시 잡히는 음수 SEE 수를 공격 스타일만으로 선택하지 않습니다. 실제 희생에 전술적 보상이 있어서 객관 탐색이 최선으로 판단한 경우는 예외입니다.
4. **초반 퀸 보존:** 14수 이내 동등하거나 불리한 국면에서 자발적인 퀸 맞교환을 피하는 데 허용하는 손실을 최대 145cp로 확대. 왕 안전/객관 탐색/성립 가능한 대안 검증은 유지. 유리할 때는 승세 보존 한도가 우선합니다.
5. **Fighting Spirit 안전 한도:** 동등·불리할 때 반복 무승부 회피 성향은 유지하되, 이미 유리할 때는 반복 회피 때문에 큰 점수 손실을 감수하지 않게 제한.

마이너피스 3개 대 퀸 등 기존 v4.9.7 Material Imbalance, 4.9.6 Fighting Spirit, 4.9.5 King Cache, 4.9.4 승세 마무리, v4.9.7 열세 무승부 정책 유지. 일반 HCE는 변경하지 않았습니다.

## 재현 및 테스트

- [ZrPyxvyd](https://lichess.org/game/ZrPyxvyd): 38.Rc4+?? Rxc4 39.bxc4가 앞선 우세를 소진한 실제 포지션을 FEN으로 재현. 깊이 4에서 v4.9.7은 `h4c4`를 골랐고, v4.9.8은 `h1g1` (38.Kg1)을 골랐습니다.
- [t4WwYxQ8](https://lichess.org/game/t4WwYxQ8): 7.c3 후 조기 퀸 교환 대신 비숍 후퇴를 유지하는 회귀 테스트를 추가했습니다.
- [OtTxOkSP](https://lichess.org/game/OtTxOkSP): 44.Bxa7+?? Kxa7 (약 -1에서 -5.5로 급락)를 재현. 마이너피스-폰-킹 재포획 위험 분류를 테스트하며 깊이 3에서 해당 수를 선택하지 않습니다.
- v4.9.8 실험 메커니즘·기존 회귀 전체 Linux x86-64 Release **CTest 11/11 PASS**.
- UCI `uci`, `isready`, `go depth 2`: **PASS**.

**한계:** 실제 3+2 시간 제약에서 같은 선택을 보장하거나 Elo 향상을 입증한 것은 아닙니다. 정적 탐색 결과가 틀린 경우에는 객관 수 자체도 오류일 수 있습니다. 추가 ARM64 11/11 테스트와 실전 대국을 확인해야 합니다.

## 운영 배포 (선택)

파일의 `source-v498.zip`과 스크립트를 그대로 둔 상태에서 Windows PowerShell 5.1에서 `deploy-v498.ps1` 실행. 배포는 서버에 격리 복사→ ARM64 전체 빌드 및 CTest 11/11 → UCI 확인 → 진행 중 대국 0 두 번 확인 → 기존 v4.9.7 바이너리 SHA 확인 → 백업 → 엔진 바이너리 단일 교체 → `jjugle-lichess`만 재시작 → 사후 확인합니다. 실패 시 자동 복구를 시도합니다.

운영 바이너리 v4.9.7 SHA256 기준:
`2ddfa8549ae60f799eaedd2aaf455ee9ff99e8022b796ce2b17cc1ab36ade695`

운영 성공 로그는 반드시 다음 세 줄을 포함해야 합니다.

```
V498_DEPLOYED=YES
JJUGLE_PM2=ONLINE
DEPLOY_EXIT=0
```

`DEPLOYED=NOT_YET_VERIFIED`는 단지 백그라운드 실행이 시작됐다는 의미입니다.

## GitHub `main` 반영 (선택)

`push-v498-github.ps1`은 `yddfhbh/HebiChess`의 `main` HEAD가 v4.9.7 업로드 커밋 `3901281c7be53174e836bfda5e933f30d5a68393`인지 검사한 뒤, `engines/jjugle-chaos/` 아래만 갱신합니다. 기존 웹 프로젝트 파일은 수정하지 않습니다. 운영 VM에는 접근하지 않습니다. 인증된 git.exe가 필요하며, `main`이 바뀌었으면 자동 중단합니다.

PowerShell 파일들은 한글 인코딩 깨짐을 막기 위해 **UTF-8 BOM**으로 저장했습니다.
